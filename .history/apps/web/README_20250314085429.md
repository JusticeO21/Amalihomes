# GitHub Actions Workflows

This project uses several GitHub Actions workflows to ensure code quality, security, and maintainability.

## CI/CD Pipeline (`ci-cd.yml`)

Handles continuous integration and deployment processes.

### Triggers
- Push to `main` or `develop` branches
- Pull requests to `main` or `develop` branches

### Actions
- ✅ Sets up Node.js environment
- 📦 Installs dependencies
- 🔍 Runs linting checks
- 📝 Performs type checking
- 🧪 Executes tests
- 🏗️ Builds the application

## Security Scanning (`security.yml`)

Performs security analysis and vulnerability checks.

### Triggers
- Push to `main` branch
- Weekly schedule (Sunday at 00:00 UTC)

### Actions
- 🔒 Runs Snyk vulnerability scanning
- 🔍 Performs CodeQL analysis

### Required Secrets
- `SNYK_TOKEN`: Required for Snyk vulnerability scanning

## Dependency Updates (`dependabot.yml`)

Automates dependency management with Dependabot.

### Configuration
- 📦 Monitors npm dependencies
- 🕒 Weekly update checks
- 🔄 Maximum 10 open pull requests
- 🏷️ Adds "dependencies" label to PRs

## Pull Request Checks (`pr-checks.yml`)

Enforces pull request standards and conventions.

### Triggers
- Pull request opened
- Pull request synchronized
- Pull request reopened

### Actions
- 📝 Validates conventional commit message format in PR titles
- 📏 Checks PR size limits:
  - Maximum 20 files
  - Maximum 500 lines

## Local Development Setup

To ensure your changes pass CI checks locally, add these scripts to your `package.json`:

```json
{
  "scripts": {
    "typecheck": "tsc --noEmit",
    "lint": "next lint",
    "test": "jest",
    "build": "next build"
  }
}
```

## Required Repository Secrets

The following secrets need to be configured in your GitHub repository settings:

1. `SNYK_TOKEN`: For security vulnerability scanning
2. `GITHUB_TOKEN`: Automatically provided by GitHub

## Workflow Maintenance

- Keep action versions updated periodically
- Review and adjust PR size limits as needed
- Update Dependabot configuration based on team needs
- Monitor workflow execution times and optimize if necessary

## Customizing Workflows

To modify these workflows:

1. Navigate to `.github/workflows/` directory
2. Edit the respective YAML files
3. Commit and push changes
4. GitHub Actions will automatically use the updated workflows

## Troubleshooting

If workflows fail:

1. Check the Actions tab in GitHub for detailed error logs
2. Verify all required secrets are properly set
3. Ensure all required dependencies are installed
4. Confirm branch protections and permissions are correctly configured

For more detailed information about GitHub Actions, visit [GitHub Actions Documentation](https://docs.github.com/en/actions).
